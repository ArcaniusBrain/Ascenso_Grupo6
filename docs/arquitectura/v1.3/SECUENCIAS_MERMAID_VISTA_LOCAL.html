11_secuencia_reserva_oferta

Ver código Mermaid
sequenceDiagram
  autonumber
  actor Coord as Coordinador
  participant S3 as S3 Seleccion
  participant Out3 as Outbox S3
  participant MQ as RabbitMQ
  participant In4 as Inbox S4
  participant H as EmitirOfertaHandler S4
  participant API as API Becas S4
  participant P as IReservaPresupuestoRemota
  participant S2 as S2 Fondos privado
  participant Repo as IOfertaRepository
  participant Out4 as Outbox S4
  S3->>Out3: Persistir PostulacionSeleccionada.v1
  Out3-->>MQ: Publicar evento confirmado
  MQ-->>In4: Entregar evento con reintentos
  In4->>H: Actualizar seleccion idempotente
  Coord->>API: POST /ofertas (postulacionId, operationId)
  API->>H: Ejecutar con identidad del token
  H->>H: Verificar seleccion y una oferta por postulacion+ciclo
  H->>P: Reservar(programaId, postulacionId, cicloId, operationId)
  P->>S2: POST reservas privado, scope fondos.reservar
  S2->>S2: Calcular monto desde Programa.MontoPorPeriodo
  S2-->>P: reservaId o rechazo
  alt Sin reserva confirmada
    H-->>API: 409 o 503 sin oferta
  else Reserva confirmada
    H->>Repo: Guardar Oferta, RegistroDecision y Outbox S4
    alt Falla commit
      H->>P: Compensar reserva idempotente
      H-->>API: Error sin oferta
    else Commit confirmado
      Repo-->>H: Confirmado
      H-->>API: 201 OfertaEmitidaRespuesta
      Out4-->>MQ: Publicar OfertaEmitida.v1
    end
  end

14_secuencia_pago_otp

Ver código Mermaid
sequenceDiagram
  autonumber
  actor Fin as Finanzas
  participant API as :ApiBecas
  participant H as :ConfirmarPagoHandler
  participant Repo as :IBecaRepository
  participant S1 as :IValidadorOtp
  participant B as :Beca
  participant Infra as :RepositorioBecaEfCore
  Fin->>API: POST /pagos con challengeId + codigo + operationId
  API->>H: Ejecutar(comando, identidad token)
  H->>Repo: Obtener Beca y Desembolso
  Repo-->>H: Beca cargada
  H->>H: Verificar permiso, alcance y estado del agregado
  alt Permiso o estado invalido
    H-->>API: Error 403/409 o 422
    API-->>Fin: ProblemDetails
  else Estado autorizado
    H->>S1: ValidarYConsumir(usuario, recurso, operacion, codigo, challenge)
    S1-->>H: OTP consumido una sola vez o rechazo
    alt OTP invalido o reutilizado
      H-->>API: 403 / 422 sin cambios
    else OTP valido
      H->>B: ConfirmarPago() y registrar evento
      H->>Repo: Guardar Beca + RegistroDecision + Outbox
      Repo->>Infra: Unidad de trabajo
      alt Conflicto de version
        Infra-->>Repo: 409
        Repo-->>H: Conflicto
        H-->>API: 409 requiere nuevo desafio
      else Commit
        Infra-->>Repo: Confirmado
        Repo-->>H: Resultado
        H-->>API: PagoConfirmadoRespuesta
      end
    end
  end

  participant IDP as Keycloak OIDC
  participant Gate as YARP
  participant S5 as API S5 Seguimiento
  participant In as Recepcion Lotes S5
  participant Out as Outbox S5
  participant MQ as RabbitMQ
  participant W as Worker S5
  participant ACL as Mapa estudiantes S5
  participant Repo as IReporteAcademicoRepository

  Uni->>Gate: POST lote con codigoEstudiante + token
  Gate->>S5: Transferir solicitud validada
  S5->>S5: Validar universidad, forma e idempotencyKey
  S5->>In: Guardar recepción del lote
  S5->>Out: Guardar evento LoteAcademicoRecibido en transacción

  S5-->>Uni: 202 LoteAceptado con id seguimiento
  Out-->>MQ: Publicar LoteAcademicoRecibido
  MQ-->>W: Entregar a Inbox de worker
  W->>ACL: Resolver universidad + codigoEstudiante
  Note over ACL: Correspondencia BecaId pertenece a ACL de S5
  ACL-->>W: BecaId interna o error de fila
  W->>Repo: Guardar reporte, RegistroDecision y Outbox
  Repo-->>W: Confirmación o error registrado
  W->>In: Registrar resultado por fila, registrado o rechazado con motivo

  Gate->>S5: Transferir consulta validada
  S5->>In: Leer resultado del lote de esa universidad

28_secuencia_reserva_reconciliacion

Ver código Mermaid
sequenceDiagram
  autonumber
  participant S4 as S4 Ofertas
  participant S2 as S2 PresupuestoPrograma
  participant Job as Reconciliador S2
  S4->>S2: POST Reservar(idempotencyKey)
  S2-->>S4: reservaId
  alt Guardado de oferta correcto
    S4->>S4: Commit Oferta + Outbox
    S4-->>S2: OfertaEmitida.v1
    S2->>S2: Vincular reserva
  else Guardado falla
    S4->>S2: Liberar(reservaId, operationId)
    opt Red caída / liberación pendiente
      Job->>S2: Detectar reserva sin vínculo y plazo excedido
      S2->>S2: Verificar estado con fuente autorizada antes de liberar
    end
  end
  Note over S2,S4: Nunca liberar solo por timeout sin comprobación: podría existir oferta confirmada con evento retrasado
